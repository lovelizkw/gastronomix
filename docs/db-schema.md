# Схема базы данных Gastronomix

База данных — PostgreSQL (облачный Neon в production, встроенный PGLite в локальной
разработке). Схема задаётся миграциями в каталоге `migrations/` и применяется
автоматически при старте приложения; применённые файлы учитываются в таблице
`_migrations` и повторно не выполняются.

## Пользователи и авторизация (better-auth)

| Таблица        | Назначение                                                        |
| -------------- | ----------------------------------------------------------------- |
| `user`         | Пользователи: id, имя, email (уникальный), флаг подтверждения, аватар |
| `session`      | Активные сессии: токен, срок действия, связь с `user`             |
| `account`      | Учётные данные и внешние провайдеры (OAuth), хеши паролей         |
| `verification` | Одноразовые коды подтверждения (email и т.п.)                     |

Схема создана миграцией `migrations/auth/0001_auth.sql` (генерируется Better Auth CLI).

## Данные приложения

### `products` — продукты пользователя («Холодильник»)

| Колонка    | Тип          | Описание                              |
| ---------- | ------------ | ------------------------------------- |
| `id`       | serial PK    | Уникальный идентификатор              |
| `user_id`  | text         | Владелец (ссылка на `user.id`)        |
| `name`     | text         | Название продукта                     |
| `category` | text         | Категория (овощи, молочное и т.д.)    |
| `qty`      | text         | Количество в свободной форме («3 шт»)|
| `created_at` | timestamptz | Дата добавления                    |

Индекс: `products_user_id_idx`. Все запросы фильтруются по `user_id` текущего
пользователя — данные изолированы per-user.

### `recipes` — рецепты (каталог + пользовательские)

| Колонка        | Тип          | Описание                                          |
| -------------- | ------------ | ------------------------------------------------- |
| `id`           | serial PK    | Уникальный идентификатор                          |
| `user_id`      | text / null  | `null` — рецепт из каталога, иначе — автор        |
| `title`        | text         | Название блюда                                    |
| `time_label`   | text         | Время приготовления («30 мин»)                    |
| `ingredients`  | text         | Ингредиенты через запятую (для поиска по холодильнику) |
| `instructions` | text         | Способ приготовления                              |
| `image`        | text         | Путь к фото (`/images/...`) или data-URL загруженного фото |
| `kcal`         | integer      | Калорийность на порцию, ккал                      |
| `protein`      | integer      | Белки, г                                          |
| `fat`          | integer      | Жиры, г                                           |
| `carbs`        | integer      | Углеводы, г                                       |
| `created_at`   | timestamptz  | Дата создания                                     |

Индекс: `recipes_user_id_idx`. Пользователь видит каталог (`user_id is null`)
и свои рецепты.

### Наполнение каталога

- `0003_seed_recipes.sql` — первые 18 рецептов;
- `0004_seed_recipes_catalog.sql` — ещё 12 рецептов, итого **30 блюд в каталоге**.

Обе миграции идемпотентны: повторно каталог не дублируется.

## Связи

```
user 1 ──── * session
user 1 ──── * account
user 1 ──── * products   (user_id)
user 1 ──── * recipes    (user_id, nullable — каталог)
```
